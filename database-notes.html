BBCT 1101

Database Systems

Complete study notes covering database concepts, database management systems, data models, relational databases, SQL, normalization, transactions, security and database administration.

1. Introduction to Database Systems

A database is an organized collection of related data that can be stored, managed and retrieved efficiently.

Database: An organized collection of related data stored in a way that allows users and applications to access and manage it.

A database system consists of the database itself, the Database Management System (DBMS), users, applications and procedures.

2. Data and Information

Data

Data consists of raw facts and figures that have not yet been processed.

Examples include names, numbers, dates and examination marks.

Information

Information is processed and organized data that has meaning and can be used for decision-making.

Example: Student marks such as 70, 65 and 80 are data. The calculated average mark is information.

3. Database Management System (DBMS)

A Database Management System is software used to create, store, organize, retrieve and manage data in databases.

Examples of DBMS

  • MySQL
  • Microsoft SQL Server
  • Oracle Database
  • PostgreSQL
  • Microsoft Access
  • SQLite

4. Functions of a DBMS

  • Data storage
  • Data retrieval
  • Data modification
  • Data security
  • Backup and recovery
  • Transaction management
  • Concurrency control
  • Data integrity management
  • User access control

5. Advantages of Database Systems

  • Reduces unnecessary duplication of data.
  • Improves data sharing.
  • Improves data security.
  • Provides backup and recovery.
  • Improves data consistency.
  • Allows multiple users to access data.
  • Makes information retrieval easier.

6. Disadvantages of Database Systems

  • Database systems can be expensive to establish.
  • They require skilled personnel.
  • Hardware and software maintenance may be costly.
  • System failure can affect many users.
  • Security must be carefully managed.

7. Database Users

Database Administrator

Responsible for managing, securing, backing up and maintaining the database system.

Database Designer

Designs the structure and relationships of the database.

Application Programmer

Develops programs that interact with databases.

End Users

People who use applications to access and work with database information.

8. Database Models

A database model describes how data is organized and related.

Common Models

  • Hierarchical model
  • Network model
  • Relational model
  • Object-oriented model
  • NoSQL models

9. Relational Database Model

The relational model organizes data into tables consisting of rows and columns.

Each table normally represents an entity or subject, while each row represents an individual record.

Example: A Students table can contain student ID, name, course and age.

10. Tables, Records and Fields

Table

A table stores related information in rows and columns.

Record

A record is a complete set of related information about one item or person.

Field

A field is a single category of information stored in a table.

Student_ID Name Course
001 John Computing
002 Mary Database

11. Entities and Attributes

Entity

An entity is a real-world object or concept about which information is stored.

Examples include Student, Teacher, Course and Department.

Attribute

An attribute describes a property of an entity.

Example: For a Student entity, attributes may include Student_ID, Name, Age and Course.

12. Primary Key

A primary key is a field or combination of fields that uniquely identifies each record in a table.

Characteristics

  • Values should be unique.
  • It should identify one record.
  • It should not normally contain NULL values.
Example: Student_ID can be used as the primary key in a Students table.

13. Foreign Key

A foreign key is a field in one table that refers to a primary key in another table.

Foreign keys are used to establish relationships between tables.

Example: A Course_ID in a Student table may reference Course_ID in a Courses table.

14. Candidate and Composite Keys

Candidate Key

A candidate key is an attribute or set of attributes that can uniquely identify a record and could potentially be selected as the primary key.

Composite Key

A composite key consists of two or more fields used together to uniquely identify a record.

15. Relationships Between Tables

Relationships describe how entities are associated with one another.

Main Types

  • One-to-One
  • One-to-Many
  • Many-to-Many

16. One-to-One Relationship

In a one-to-one relationship, one record in one table is associated with one record in another table.

Example: One person may have one passport record, while each passport belongs to one person.

17. One-to-Many Relationship

In a one-to-many relationship, one record in one table can be related to many records in another table.

Example: One department can have many students.

18. Many-to-Many Relationship

In a many-to-many relationship, many records in one table can be related to many records in another table.

Example: A student can take many courses, and a course can have many students.

Many-to-many relationships are commonly implemented using an intermediate or junction table.

19. Entity Relationship Diagram (ERD)

An Entity Relationship Diagram is a visual representation of entities, attributes and relationships in a database.

Common ERD Components

  • Entities
  • Attributes
  • Relationships
  • Primary keys
  • Foreign keys

20. Database Normalization

Normalization is the process of organizing database tables to reduce unnecessary duplication and improve data integrity.

Objectives

  • Reduce data redundancy.
  • Prevent update problems.
  • Improve consistency.
  • Improve database structure.

21. First Normal Form (1NF)

A table is in First Normal Form when each field contains atomic values and repeating groups are removed.

Key idea: One cell should normally contain one value rather than a list of multiple values.

22. Second Normal Form (2NF)

A table is in Second Normal Form when it is in 1NF and non-key attributes depend on the whole primary key.

This is particularly important when a table has a composite primary key.

23. Third Normal Form (3NF)

A table is in Third Normal Form when it is in 2NF and non-key attributes do not depend on other non-key attributes.

Simple idea: Non-key information should depend on the key, the whole key, and nothing but the key.

24. Database Redundancy

Data redundancy occurs when the same information is stored unnecessarily in multiple places.

Problems Caused by Redundancy

  • Wasted storage.
  • Inconsistent information.
  • More difficult updates.
  • Increased possibility of errors.

25. SQL

SQL stands for Structured Query Language. It is widely used to create, manage and retrieve data from relational databases.

Main SQL Categories

  • DDL – Data Definition Language
  • DML – Data Manipulation Language
  • DQL – Data Query Language
  • DCL – Data Control Language
  • TCL – Transaction Control Language

26. Creating a Database

CREATE DATABASE StudyHub;

The CREATE DATABASE statement creates a new database.

27. Creating a Table

CREATE TABLE Students
(
    Student_ID INT PRIMARY KEY,
    Name VARCHAR(100),
    Age INT,
    Course VARCHAR(100)
);

28. Inserting Data

INSERT INTO Students
(Student_ID, Name, Age, Course)

VALUES
(1, 'John', 20, 'Computing');

29. Selecting Data

SELECT * FROM Students;

The SELECT statement is used to retrieve data from a table.

Select Specific Columns

SELECT Name, Course
FROM Students;

30. WHERE Clause

The WHERE clause is used to filter records according to a condition. 

SELECT *
FROM Students
WHERE Age > 18;

31. UPDATE Statement

UPDATE is used to modify existing records. 

UPDATE Students

SET Age = 21

WHERE Student_ID = 1;
Important: Always use an appropriate WHERE condition when updating specific records.

32. DELETE Statement

DELETE is used to remove records from a table. 

DELETE FROM Students
WHERE Student_ID = 1;

33. SQL Sorting

The ORDER BY clause sorts query results. 

SELECT *
FROM Students
ORDER BY Name ASC;

ASC sorts in ascending order while DESC sorts in descending order.

34. Aggregate Functions

Aggregate functions perform calculations on groups of values.

  • COUNT()
  • SUM()
  • AVG()
  • MAX()
  • MIN()
SELECT AVG(Age)
FROM Students;

35. GROUP BY and HAVING

GROUP BY groups records that have the same values in specified columns. 

SELECT Course, COUNT(*)
FROM Students
GROUP BY Course;

HAVING can be used to filter grouped results.

36. SQL Joins

Joins are used to combine information from multiple tables.

Common Joins

  • INNER JOIN
  • LEFT JOIN
  • RIGHT JOIN
  • FULL OUTER JOIN

37. INNER JOIN

An INNER JOIN returns records that have matching values in both tables. 

SELECT Students.Name, Courses.Course_Name

FROM Students

INNER JOIN Courses

ON Students.Course_ID =
   Courses.Course_ID;

38. Database Constraints

Constraints are rules applied to database columns to maintain data accuracy and integrity.

Common Constraints

  • PRIMARY KEY
  • FOREIGN KEY
  • NOT NULL
  • UNIQUE
  • CHECK
  • DEFAULT

39. Data Integrity

Data integrity means maintaining the accuracy, consistency and reliability of data.

Types

  • Entity integrity
  • Referential integrity
  • Domain integrity
  • User-defined integrity

40. Transactions

A transaction is a logical unit of database operations that should be completed successfully as a whole.

ACID Properties

  • Atomicity: A transaction is treated as one complete unit.
  • Consistency: The database remains valid before and after the transaction.
  • Isolation: Concurrent transactions should not improperly interfere with one another.
  • Durability: Committed changes remain stored even after failures.

41. Database Security

Database security protects stored information from unauthorized access, modification, destruction or disclosure.

Security Measures

  • User authentication
  • Authorization
  • Strong passwords
  • Encryption
  • Access control
  • Regular backups
  • Monitoring and auditing

42. Database Backup and Recovery

A database backup is a copy of database information that can be used to restore data after loss or damage.

Possible Causes of Data Loss

  • Hardware failure
  • Software failure
  • Human error
  • Malware
  • Accidental deletion
  • Natural disasters

43. Database Administration

Database administration involves managing the performance, security, availability and reliability of a database system.

Responsibilities of a DBA

  • Database installation
  • User management
  • Security management
  • Backup and recovery
  • Performance monitoring
  • Database maintenance

44. Database Views

A view is a virtual table based on the result of a query. It can be used to simplify access to information or restrict what certain users can see. 

CREATE VIEW StudentView AS

SELECT Name, Course

FROM Students;

45. Indexes

An index is a database structure that can improve the speed of data retrieval.

Indexes can improve query performance, but they may require additional storage and can increase the cost of some data modification operations.

46. Database Applications

Database systems are used in many organizations and industries.

  • Banks
  • Hospitals
  • Schools and universities
  • Government institutions
  • Businesses
  • Airlines
  • Online shopping platforms
  • Libraries

47. Database Design Process

  1. Identify system requirements.
  2. Identify entities.
  3. Identify attributes.
  4. Identify relationships.
  5. Develop an ER diagram.
  6. Convert the design into tables.
  7. Identify primary and foreign keys.
  8. Normalize the tables.
  9. Implement the database.
  10. Test and maintain the system.

48. Practical Database Example

Consider a simple student management system.

Students Table

Student_ID Name Age Course_ID
1 John 20 C01
2 Mary 21 C02

Courses Table

Course_ID Course_Name
C01 Computer Science
C02 Database Systems

The Course_ID in the Students table can act as a foreign key that references the Course_ID in the Courses table.

49. Common Database Problems

  • Duplicate records
  • Incorrect data
  • Unauthorized access
  • Data loss
  • Poor database design
  • Slow queries
  • Weak passwords
  • Failure to perform backups

Solutions

  • Use normalization.
  • Apply constraints.
  • Use appropriate indexes.
  • Implement security controls.
  • Perform regular backups.
  • Monitor database performance.

50. Important Database Terms

  • Database: Organized collection of related data.
  • DBMS: Software used to manage databases.
  • Table: Structure containing rows and columns.
  • Record: A row containing related information.
  • Field: A column representing a data attribute.
  • Primary Key: Uniquely identifies a record.
  • Foreign Key: Links related tables.
  • SQL: Language used to work with relational databases.
  • Normalization: Process of organizing data to reduce redundancy.
